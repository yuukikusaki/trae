### 一、I/O管理概述

#### I/O设备分类

| 分类维度 | 类型 |
|----------|------|
| 传输速率 | 低速（键盘/鼠标）、中速（打印机）、高速（磁盘） |
| 信息交换单位 | **块设备**（磁盘，以块为单位）、**字符设备**（键盘，以字节为单位） |
| 共享属性 | 独占设备、共享设备、虚拟设备 |

### 二、I/O软件层次结构

```
用户层I/O软件（库函数如printf/scanf）
        ↓
设备独立性软件（统一接口、命名、保护、缓冲、分配）
        ↓
设备驱动程序（与硬件打交道，每类设备一个驱动）
        ↓
中断处理程序（处理I/O完成中断）
        ↓
硬件（I/O设备 + 控制器）
```

> 🔥 **设备独立性**：用户程序用逻辑设备名，OS映射到物理设备。如`/dev/sda`不随硬件更换而需改代码。

### 三、SPOOLing 技术（假脱机）⭐

| 概念 | 说明 |
|------|------|
| **核心思想** | 用磁盘模拟独占设备，将独占设备变为共享设备 |
| 输入井/输出井 | 磁盘上暂存输入/输出数据的区域 |
| 输入进程/输出进程 | 负责数据在井和设备间传送（**守护进程**） |
| **典型应用** | 共享打印机（多用户同时"打印"→数据入输出井→排队输出） |

> 🔥 SPOOLing将**独占设备虚拟为共享设备**，体现OS的"虚拟"特征。

### 四、缓冲区管理 ⭐

#### 1. 为什么要缓冲？

- 缓解CPU与I/O设备**速度不匹配**
- 减少设备**中断频率**
- 提高CPU与I/O设备的**并行度**

#### 2. 缓冲类型对比

| 类型 | 结构 | 并行处理能力 |
|------|------|------------|
| **单缓冲** | 1个缓冲区 | CPU处理 + I/O输入 交替（时间 ≈ max(C, T) + M） |
| **双缓冲** | 2个缓冲区交替 | CPU和I/O可**同时**工作（时间 ≈ max(C, T)） |
| **循环缓冲** | 多个缓冲区环形排列 | 类似双缓冲，适合大量数据 |
| **缓冲池** | 系统公用缓冲区集合 | 三种队列：空缓冲/输入/输出队列 |

其中 C=CPU处理时间，T=I/O传输时间，M=数据搬移时间。

#### 3. I/O控制方式回顾（计组+OS交叉）

| 方式 | CPU干预 | 数据传送 | 适用 |
|------|---------|----------|------|
| 程序直接控制 | CPU全程控制 | CPU | 简单慢速设备 |
| 中断方式 | 仅开始和结束时干预 | CPU | 中低速设备 |
| DMA | 仅开始和结束时干预 | **DMA控制器** | 高速块设备（磁盘） |
| 通道 | 最少干预 | **通道处理器** | 大型机多设备 |

### 五、易错点

- ❌ SPOOLing是真正实现了设备并行 → ✅ SPOOLing是逻辑上的"并行"（假脱机），物理上串行
- ❌ 双缓冲一定比单缓冲快一倍 → ✅ 取决于C和T的相对大小：T>C时有效，C≥T时差异不大
- ⚠️ DMA传送单位是**数据块**；中断方式传送单位是**字节/字**
