### 一、进程与线程 ⭐

#### 1. 进程状态五态模型

```
           ┌──────────────────────┐
           ↓                      │
        就绪态 →(调度)→ 运行态 →(时间片完)→ 就绪态
           ↑            │
           │        (等待事件)
           │            ↓
           └── 阻塞态 ──┘(事件发生)
                          │
                    创建态 ─→ 终止态
```

| 状态 | 说明 |
|------|------|
| 创建态 | 进程正在被创建，尚未就绪 |
| 就绪态 | 除CPU外一切就绪，等待调度 |
| 运行态 | 正在CPU上执行 |
| 阻塞态 | 等待某事件（I/O等），即使给予CPU也无法运行 |
| 终止态 | 进程执行完毕，等待回收 |

> 🔥 **关键区分**：就绪→运行是**调度程序**做的事；运行→阻塞是**进程自身**主动做的事。

#### 2. 进程 vs 线程

| 对比维度 | 进程 | 线程 |
|----------|------|------|
| 资源拥有 | **独立**资源（地址空间、文件等） | **共享**所属进程的资源 |
| 调度 | 传统OS中进程是调度单位 | 线程是**独立调度的基本单位** |
| 并发性 | 进程间并发 | 同一进程内线程可并发 |
| 系统开销 | 创建/切换开销大 | 创建/切换开销小 |
| 通信 | 需IPC机制 | 直接读写进程内共享数据 |

#### 3. 进程通信（IPC）

| 方式 | 特点 |
|------|------|
| **共享内存** | 最快，需互斥同步机制配合 |
| **消息传递** | 发送/接收原语，适合跨网络（套接字亦属此列） |
| **管道（Pipe）** | 半双工，用于父子进程；匿名管道 / 命名管道(FIFO) |

### 二、处理机调度 ⭐

#### 1. 三级调度

| 层次 | 别称 | 频率 | 功能 |
|------|------|------|------|
| **作业调度** | 高级调度 | 低 | 外存→内存（选哪个作业进入） |
| **内存调度** | 中级调度 | 中 | 挂起/换入换出（提高内存利用率） |
| **进程调度** | 低级调度 | **最高** | 就绪队列→CPU |

#### 2. 经典调度算法对比

| 算法 | 思想 | 优缺点 | 是否抢占 |
|------|------|--------|----------|
| **FCFS** | 先来先服务 | 简单，对短作业不利 | 否 |
| **SJF/SPF** | 短作业/短进程优先 | 平均等待时间最小（默认非抢占） | 可有抢占版(SRTN) |
| **优先级** | 按优先级调度 | 可能**饥饿**（低优先级永远得不到CPU） | 可有抢占版 |
| **高响应比** | $R = \frac{等待时间+要求服务时间}{要求服务时间}$ | 折中，兼顾长短作业 | 否 |
| **RR** | 固定时间片轮转 | 适合分时，时间片大小很关键 | **是** |
| **多级反馈队列** | 多队列+时间片递增+抢占 | 综合最优，兼顾所有类型 | **是** |

> 🔥 **SJF平均等待时间最小**（非抢占前提下），这是408常考的结论。

### 三、进程同步与互斥 ⭐（408大题重灾区）

#### 1. 基本原则

| 原则 | 含义 |
|------|------|
| **空闲让进** | 临界区空闲时允许进程进入 |
| **忙则等待** | 临界区被占用时其他进程等待 |
| **有限等待** | 等待时间有限，不能死等 |
| **让权等待** | 等不到时释放CPU，不能忙等 |

#### 2. 信号量（PV操作）⭐

```
P操作（wait）：S.value--; if S.value < 0 → 阻塞自己
V操作（signal）：S.value++; if S.value ≤ 0 → 唤醒一个等待进程
```

| 信号量类型 | 初值 | 用途 |
|-----------|------|------|
| 互斥信号量 | 1 | 保护临界区 |
| 同步信号量 | 0 | 协调执行顺序 |
| 资源信号量 | N（资源数） | 控制资源分配 |

#### 3. 经典同步问题模板

**生产者-消费者**（必会）：
- `empty = N`（空缓冲区数）, `full = 0`（满缓冲区数）, `mutex = 1`
- 生产者：P(empty) → P(mutex) → 放入 → V(mutex) → V(full)
- 消费者：P(full) → P(mutex) → 取出 → V(mutex) → V(empty)

**读者-写者**：
- 读者优先：第一个读者P(rw)，最后一个读者V(rw)
- 写者优先/公平竞争：需要额外信号量控制

**哲学家就餐**：
- 防死锁方案：限制最多4人就餐 / 奇数先拿左、偶数先拿右 / 同时拿两根筷子

### 四、死锁 ⭐

#### 1. 死锁4个必要条件（缺一不可）

1. **互斥**：资源一次只能被一个进程使用
2. **不可剥夺**：已分配的资源不能被强行夺走
3. **请求与保持**：已拥有资源的进程继续请求被阻塞
4. **环路等待**：进程-资源图中有循环等待链

#### 2. 死锁处理策略

| 策略 | 方法 | 重点 |
|------|------|------|
| **预防** | 破坏4个必要条件之一 | 破坏"不可剥夺"或"环路等待"较可行 |
| **避免** | **银行家算法** | 每次分配前判断是否存在安全序列 |
| **检测** | 资源分配图化简 / 死锁定理 | 定期检测 |
| **解除** | 撤销进程 / 剥夺资源 / 回滚 | — |

#### 3. 银行家算法（408大题高频）

- **数据结构**：Available、Max、Allocation、Need（= Max - Allocation）
- **安全性检查**：找出安全序列，满足 Need ≤ Available 即可完成并释放
- **请求检查**：Request ≤ Need 且 Request ≤ Available → 试分配 → 安全性检查

> 🔥 **死锁定理**：资源分配图**不可完全化简** ⇔ 存在死锁

### 五、易错点

- ❌ 就绪→阻塞 → ✅ 只有运行→阻塞，没有就绪→阻塞！
- ❌ P操作是减1、V操作是加1 → ✅ P是荷兰语Proberen（尝试），V是Verhogen（增加）
- ⚠️ PV操作中，互斥P操作必须在同步P操作**之后**（否则可能死锁）
- ⚠️ 银行家算法中，进行安全性检查前必须先**试分配**再判断
