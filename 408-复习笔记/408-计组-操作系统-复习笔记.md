## 📘 计组 第1章 计算机系统概述

### 一、核心考点

#### 1. 冯·诺依曼结构 vs 哈佛结构

| 对比维度 | 冯·诺依曼结构 | 哈佛结构 |
|---------|-------------|---------|
| 存储方式 | 指令和数据**共用**存储器 | 指令和数据**分开**存储 |
| 总线 | 共享一条总线 | 独立指令总线 + 数据总线 |
| 并行性 | 取指和取数**不能并行** | 取指和取数**可并行** |
| 典型应用 | PC 通用计算机 | DSP、嵌入式系统 |

> 🔥 **408常考**：冯·诺依曼的"存储程序"思想——程序以指令形式事先存入内存，CPU 逐条取出执行。

#### 2. 计算机系统层次结构

```
虚拟机器M5（应用语言）—— 用户
    ↑ 翻译（编译程序）
虚拟机器M4（高级语言）—— 程序员
    ↑ 翻译（编译/解释程序）
虚拟机器M3（汇编语言）—— 汇编程序员
    ↑ 翻译（汇编程序）
虚拟机器M2（操作系统） —— 系统软件
    ↑ 部分解释（操作系统）
实际机器M1（机器语言） —— 硬件
    ↑ 解释（微程序/硬布线）
微程序机器M0（微指令） —— 硬件内核
```

> 💡 **记忆口诀**：上层翻译、下层解释；M0~M2 是实际机器，M3~M5 是虚拟机器。

#### 3. 计算机性能指标 ⭐

**核心公式（必背）**：

| 指标 | 公式 | 单位 |
|------|------|------|
| CPU主频 | $f = \frac{1}{时钟周期T}$ | Hz |
| CPI | $CPI = \frac{总时钟周期数}{总指令数}$ | — |
| 程序CPU执行时间 | $T_{CPU} = IN \times CPI \times T_c$ | s |
| MIPS | $MIPS = \frac{f}{CPI \times 10^6}$ | 百万条/秒 |
| MFLOPS | $MFLOPS = \frac{浮点操作次数}{执行时间 \times 10^6}$ | 百万次/秒 |

> 🔥 **关键**：$T_{CPU} = IN \times CPI \times T_c = \frac{IN \times CPI}{f}$

### 二、易错点

- ❌ **错误**：主频高的 CPU 一定快 → ✅ 还与 CPI 和 ISA 有关
- ❌ **错误**：MIPS 可以直接比较不同机器的性能 → ✅ 不同指令集的 MIPS 不可比
- ⚠️ 吞吐量 ≠ 响应时间；吞吐量强调"系统整体处理能力"

## 📗 操作系统 第1章 操作系统概述

### 一、核心考点

#### 1. 操作系统的4个基本特征 ⭐

| 特征 | 含义 | 408出题角度 |
|------|------|------------|
| **并发** | 宏观上同时、微观上交替执行 | 与并行区分；单核只有并发没有并行 |
| **共享** | 资源被多个并发进程共同使用 | 互斥共享（打印机）vs 同时共享（磁盘） |
| **虚拟** | 将物理实体映射为多个逻辑对应物 | 虚拟内存、虚拟处理器（时分复用/空分复用） |
| **异步** | 进程走走停停，不可预知 | 由并发+共享导致 |

> 🔥 **并发 vs 并行**：并发是逻辑上的"同时"，并行是物理上的"同时"（需多核）。

#### 2. 内核态 vs 用户态 ⭐

| 对比 | 用户态（目态） | 内核态（管态） |
|------|--------------|--------------|
| 权限 | 只能执行非特权指令 | 可执行所有指令（含特权指令） |
| 程序 | 普通用户程序 | 操作系统内核 |
| 切换 | 通过**系统调用/中断/异常**进入内核态 | 中断返回时回到用户态 |
| PSW 标志位 | 0（或1，看具体体系结构） | 1（或0） |

> 💡 **访管指令**：用户态下主动切换到内核态的唯一方式（非特权指令）。

#### 3. 中断与异常 ⭐

| 对比 | 中断（外中断） | 异常（内中断/陷入） |
|------|-------------|-----------------|
| 来源 | CPU **外部**（I/O设备等） | CPU **内部**（指令执行时） |
| 与指令同步 | **异步** | **同步** |
| 可否屏蔽 | 可屏蔽/不可屏蔽 | 不可屏蔽 |
| 典型例子 | 时钟中断、I/O完成 | 缺页、除零、非法指令、断点 |
| 处理返回 | 返回**下一条**指令 | 除缺页外，通常返回**当前**指令或终止 |

#### 4. 系统调用 ⭐

- **定义**：用户在程序中调用操作系统提供的服务接口
- **过程**：用户程序 → 传参 → 执行陷入指令 → 内核态 → 系统调用处理 → 返回用户态
- **常见系统调用**：`fork()`（进程创建）、`open()`（文件打开）、`read()`/`write()`、`malloc()`（底层是 `brk/mmap`）
- ⚠️ **系统调用 ≠ 库函数**：`printf` 是库函数，底层调用了 `write` 系统调用

#### 5. 操作系统体系结构

| 类型 | 特点 | 优缺点 |
|------|------|--------|
| 宏内核 | 全部功能在内核态 | 高性能，但庞大复杂 |
| 微内核 | 最核心功能在内核，其余在用户态服务 | 可靠易扩展，但频繁切换开销大 |
| 模块化 | 面向对象，可动态加载模块 | Linux 和 Windows 采用 |

### 二、易错点

- ❌ **错误**：系统调用就是调用库函数 → ✅ 系统调用是内核接口，库函数封装了系统调用
- ❌ **错误**：中断和异常一回事 → ✅ 中断来自外部、异步；异常来自内部、同步
- ⚠️ "访管指令"是用户态执行的非特权指令，执行后 CPU 才进入内核态

## 📘 计组 第2章 数据的表示和运算

### 一、数制与编码

#### 1. 进制转换速查

| 转换 | 方法 |
|------|------|
| 任意进制 → 十进制 | 按权展开求和 |
| 十进制 → R进制（整数） | 除R取余，倒序排列 |
| 十进制 → R进制（小数） | 乘R取整，正序排列 |
| 二进制 → 八进制 | 3位一组 |
| 二进制 → 十六进制 | 4位一组 |

#### 2. 常见编码

| 编码 | 特点 |
|------|------|
| **BCD码** | 4位二进制表示1位十进制（8421码最常见） |
| **余3码** | = 8421码 + 3（0011），是一种**无权码** |
| **ASCII** | 7位编码，共128个字符 |
| **汉字编码** | 输入码 → 国标码 → 机内码（国标码+8080H） |

### 二、定点数的表示 ⭐（核心考点）

#### 1. 四种机器数对比

|  | 原码 | 反码 | 补码 | 移码 |
|--|------|------|------|------|
| **正数** | 符号0+绝对值 | 同原码 | 同原码 | 补码符号位取反 |
| **负数** | 符号1+绝对值 | 符号1+各位取反 | 反码+1 | 补码符号位取反 |
| **+0** | 0000 | 0000 | 0000 | 1000 |
| **-0** | 1000 | 1111 | 0000（唯一） | 1000 |
| **表示范围** | $-(2^{n-1}-1)$ ~ $2^{n-1}-1$ | 同原码 | $-2^{n-1}$ ~ $2^{n-1}-1$ | 同补码 |
| **用途** | 真值直观 | 中间表示 | **运算用** | 浮点阶码 |

> 🔥 **补码符号扩展**：正数补0，负数补1（算术移位规则同理）

#### 2. 定点数移位运算

| 移位类型 | 操作 | 补码注意 |
|----------|------|----------|
| 算术左移 | 各位左移，低位补0 | 符号位不变，移出位≠新符号位→溢出 |
| 算术右移 | 各位右移 | 正数补0，**负数补1**（与原码不同！） |
| 逻辑移位 | 无符号数移动 | 一律补0 |

#### 3. 定点数加减与溢出判断 ⭐

**补码加减公式**：
- $[A+B]_{补} = [A]_{补} + [B]_{补}$ （mod $2^n$）
- $[A-B]_{补} = [A]_{补} + [-B]_{补}$

**溢出判断三种方法**：

| 方法 | 规则 |
|------|------|
| **单符号位** | 两正数加得负数，或两负数加得正数 → 溢出 |
| **进位判断** | $C_n \oplus C_{n-1} = 1$ → 溢出（符号位进位 ≠ 最高数值位进位） |
| **双符号位（变形补码）** | 00=正，11=负，01=正溢，10=负溢 |

#### 4. 定点乘法（Booth算法）简记

- 在原码乘法基础上 + 符号处理
- **补码Booth算法**核心：根据 $y_i y_{i+1}$ 之差决定 +[X]补 / +0 / +[-X]补
- 408以选择题为主，理解原理即可

### 三、浮点数的表示与运算 ⭐

#### 1. IEEE 754 单精度格式

```
[ S (1位) | E (8位, 阶码) | M (23位, 尾数) ]
```

| 参数 | 单精度 (float) | 双精度 (double) |
|------|---------------|-----------------|
| 符号位 | 1 | 1 |
| 阶码位 | 8 | 11 |
| 尾数位 | 23 | 52 |
| **偏置值** | **127** | **1023** |
| 总位数 | 32 | 64 |

> 🔥 **真值公式**：$x = (-1)^S \times (1.M) \times 2^{E-127}$

- 阶码全0：非规格化数（尾数隐含位为0）
- 阶码全1、尾数全0：无穷大
- 阶码全1、尾数非0：NaN

#### 2. 浮点数加减步骤（必背5步）

```
① 对阶：小阶向大阶看齐（尾数右移）
② 尾数求和
③ 规格化：左规/右规
④ 舍入：0舍1入 / 恒置1 / 截断
⑤ 溢出判断：阶码是否溢出
```

### 四、易错点

- ❌ 补码负数右移补1，原码负数右移也补1 → ✅ 原码负数右移**补0**！
- ❌ IEEE 754 的尾数最高位是1 → ✅ 规格化时隐含"1."不存储，阶码偏置值要减
- ⚠️ 对阶时**小阶对大阶**，不是大阶对小阶（防止精度损失）

## 📗 操作系统 第2章 进程管理

### 一、进程与线程 ⭐

#### 1. 进程状态五态模型

```
           ┌──────────────────────┐
           ↓                      │
        就绪态 →(调度)→ 运行态 →(时间片完)→ 就绪态
           ↑            │
           │        (等待事件)
           │            ↓
           └── 阻塞态 ──┘(事件发生)
                          │
                    创建态 ─→ 终止态
```

| 状态 | 说明 |
|------|------|
| 创建态 | 进程正在被创建，尚未就绪 |
| 就绪态 | 除CPU外一切就绪，等待调度 |
| 运行态 | 正在CPU上执行 |
| 阻塞态 | 等待某事件（I/O等），即使给予CPU也无法运行 |
| 终止态 | 进程执行完毕，等待回收 |

> 🔥 **关键区分**：就绪→运行是**调度程序**做的事；运行→阻塞是**进程自身**主动做的事。

#### 2. 进程 vs 线程

| 对比维度 | 进程 | 线程 |
|----------|------|------|
| 资源拥有 | **独立**资源（地址空间、文件等） | **共享**所属进程的资源 |
| 调度 | 传统OS中进程是调度单位 | 线程是**独立调度的基本单位** |
| 并发性 | 进程间并发 | 同一进程内线程可并发 |
| 系统开销 | 创建/切换开销大 | 创建/切换开销小 |
| 通信 | 需IPC机制 | 直接读写进程内共享数据 |

#### 3. 进程通信（IPC）

| 方式 | 特点 |
|------|------|
| **共享内存** | 最快，需互斥同步机制配合 |
| **消息传递** | 发送/接收原语，适合跨网络（套接字亦属此列） |
| **管道（Pipe）** | 半双工，用于父子进程；匿名管道 / 命名管道(FIFO) |

### 二、处理机调度 ⭐

#### 1. 三级调度

| 层次 | 别称 | 频率 | 功能 |
|------|------|------|------|
| **作业调度** | 高级调度 | 低 | 外存→内存（选哪个作业进入） |
| **内存调度** | 中级调度 | 中 | 挂起/换入换出（提高内存利用率） |
| **进程调度** | 低级调度 | **最高** | 就绪队列→CPU |

#### 2. 经典调度算法对比

| 算法 | 思想 | 优缺点 | 是否抢占 |
|------|------|--------|----------|
| **FCFS** | 先来先服务 | 简单，对短作业不利 | 否 |
| **SJF/SPF** | 短作业/短进程优先 | 平均等待时间最小（默认非抢占） | 可有抢占版(SRTN) |
| **优先级** | 按优先级调度 | 可能**饥饿**（低优先级永远得不到CPU） | 可有抢占版 |
| **高响应比** | $R = \frac{等待时间+要求服务时间}{要求服务时间}$ | 折中，兼顾长短作业 | 否 |
| **RR** | 固定时间片轮转 | 适合分时，时间片大小很关键 | **是** |
| **多级反馈队列** | 多队列+时间片递增+抢占 | 综合最优，兼顾所有类型 | **是** |

> 🔥 **SJF平均等待时间最小**（非抢占前提下），这是408常考的结论。

### 三、进程同步与互斥 ⭐（408大题重灾区）

#### 1. 基本原则

| 原则 | 含义 |
|------|------|
| **空闲让进** | 临界区空闲时允许进程进入 |
| **忙则等待** | 临界区被占用时其他进程等待 |
| **有限等待** | 等待时间有限，不能死等 |
| **让权等待** | 等不到时释放CPU，不能忙等 |

#### 2. 信号量（PV操作）⭐

```
P操作（wait）：S.value--; if S.value < 0 → 阻塞自己
V操作（signal）：S.value++; if S.value ≤ 0 → 唤醒一个等待进程
```

| 信号量类型 | 初值 | 用途 |
|-----------|------|------|
| 互斥信号量 | 1 | 保护临界区 |
| 同步信号量 | 0 | 协调执行顺序 |
| 资源信号量 | N（资源数） | 控制资源分配 |

#### 3. 经典同步问题模板

**生产者-消费者**（必会）：
- `empty = N`（空缓冲区数）, `full = 0`（满缓冲区数）, `mutex = 1`
- 生产者：P(empty) → P(mutex) → 放入 → V(mutex) → V(full)
- 消费者：P(full) → P(mutex) → 取出 → V(mutex) → V(empty)

**读者-写者**：
- 读者优先：第一个读者P(rw)，最后一个读者V(rw)
- 写者优先/公平竞争：需要额外信号量控制

**哲学家就餐**：
- 防死锁方案：限制最多4人就餐 / 奇数先拿左、偶数先拿右 / 同时拿两根筷子

### 四、死锁 ⭐

#### 1. 死锁4个必要条件（缺一不可）

1. **互斥**：资源一次只能被一个进程使用
2. **不可剥夺**：已分配的资源不能被强行夺走
3. **请求与保持**：已拥有资源的进程继续请求被阻塞
4. **环路等待**：进程-资源图中有循环等待链

#### 2. 死锁处理策略

| 策略 | 方法 | 重点 |
|------|------|------|
| **预防** | 破坏4个必要条件之一 | 破坏"不可剥夺"或"环路等待"较可行 |
| **避免** | **银行家算法** | 每次分配前判断是否存在安全序列 |
| **检测** | 资源分配图化简 / 死锁定理 | 定期检测 |
| **解除** | 撤销进程 / 剥夺资源 / 回滚 | — |

#### 3. 银行家算法（408大题高频）

- **数据结构**：Available、Max、Allocation、Need（= Max - Allocation）
- **安全性检查**：找出安全序列，满足 Need ≤ Available 即可完成并释放
- **请求检查**：Request ≤ Need 且 Request ≤ Available → 试分配 → 安全性检查

> 🔥 **死锁定理**：资源分配图**不可完全化简** ⇔ 存在死锁

### 五、易错点

- ❌ 就绪→阻塞 → ✅ 只有运行→阻塞，没有就绪→阻塞！
- ❌ P操作是减1、V操作是加1 → ✅ P是荷兰语Proberen（尝试），V是Verhogen（增加）
- ⚠️ PV操作中，互斥P操作必须在同步P操作**之后**（否则可能死锁）
- ⚠️ 银行家算法中，进行安全性检查前必须先**试分配**再判断

## 📘 计组 第3章 存储系统

### 一、存储器层次结构

```
       ┌──────────────────────────────┐
       │ CPU寄存器      ← 最快/最贵/最小
       │  Cache(SRAM)   ← 命中率关键
       │  主存(DRAM)    ← 运行程序的场所
       │  外存(磁盘/SSD)← 最慢/最便宜/最大
       └──────────────────────────────┘
```

> 🔥 **两大原理**：时间局部性 + 空间局部性 → 层次结构的设计依据

### 二、主存储器

#### 1. SRAM vs DRAM（高频考点）

| 对比 | SRAM | DRAM |
|------|------|------|
| 存储单元 | 6个MOS管（触发器） | 1个MOS管+1个电容 |
| 是否需要刷新 | **否** | **是**（电容漏电，需定期刷新） |
| 速度 | 快（用作Cache） | 慢（用作主存） |
| 集成度 | 低 | 高 |
| 功耗 | 大 | 小 |
| 成本 | 高 | 低 |
| **破坏性读出** | 否 | **是**（读后需重写） |

#### 2. 存储器芯片扩展

| 扩展类型 | 操作 | 地址线 | 数据线 |
|----------|------|--------|--------|
| **位扩展** | 多片并联，共享地址 | 不变 | 每片贡献部分数据线 |
| **字扩展** | 片选信号选择芯片 | 增加（高位地址做片选） | 不变 |
| **字位同时扩展** | 先位扩展一组，再字扩展多组 | 增加 | 合并 |

#### 3. 多模块存储器 ⭐

| 方式 | 特点 | 适用场景 |
|------|------|----------|
| **高位交叉编址** | 高位地址选模块，顺序访问同一模块 | 容量扩展 |
| **低位交叉编址** | 低位地址选模块，相邻地址在不同模块 | **流水线存取**（带宽提升m倍） |

> 🔥 低位交叉：第 i 个地址在模块 `(i mod m)` 中，可实现**多模块流水**。

### 三、Cache（高速缓冲存储器）⭐

#### 1. Cache映射方式（必考计算）

| 映射方式 | 结构 | 特点 | 冲突概率 |
|----------|------|------|----------|
| **直接映射** | 主存块 → 固定Cache行（i mod 行数） | 简单，命中率低 | 高 |
| **全相联映射** | 主存块 → 任意Cache行 | 灵活，成本高 | 低 |
| **组相联映射** | 主存块 → 固定组，组内任意行 | 折中 | 中 |

**地址划分对比**：

| 映射方式 | 地址结构 |
|----------|----------|
| 直接映射 | 标记 \| 行号 \| 块内偏移 |
| 全相联 | 标记 \| 块内偏移 |
| K路组相联 | 标记 \| 组号 \| 块内偏移 |

> 🔥 **组相联计算**：组数 = Cache行数 / K（K为每组行数）；组号位数 = log₂(组数)

#### 2. Cache替换算法

| 算法 | 规则 | 性能 |
|------|------|------|
| **随机(RAND)** | 随机选一块替换 | 不稳定 |
| **FIFO** | 先进先出 | 可能出现Belady异常 |
| **LRU** | 替换最久未使用的 | 最优（接近OPT），但实现复杂 |
| **OPT** | 替换未来最久不用的 | 理论最优，不可实现（用于参考） |

#### 3. Cache写策略

| 策略 | 写命中 | 写不命中 |
|------|--------|----------|
| **写直达(Write-through)** | 同时写Cache+主存 | 直接写主存（不调块） |
| **写回(Write-back)** | 仅写Cache，标记脏位 | 先调入块，再写Cache |

> 🔥 **脏位(Dirty Bit)**：写回法的关键——替换时脏块需写回主存。

#### 4. Cache性能 ⭐

- **命中率 h** = Cache命中次数 / 总访问次数
- **平均访问时间**：$T_{avg} = h \times T_c + (1-h) \times T_m$
- **访问效率**：$e = T_c / T_{avg}$

### 四、虚拟存储器（计组视角）⭐

#### 1. 三种虚拟存储器

| 类型 | 划分单位 | 地址结构 |
|------|----------|----------|
| **页式** | 固定大小的页 | 虚页号 + 页内偏移 |
| **段式** | 可变大小的段 | 段号 + 段内偏移 |
| **段页式** | 段内再分页 | 段号 + 段内页号 + 页内偏移 |

#### 2. TLB（快表）⭐

- **本质**：页表项的Cache（用相联存储器实现）
- **过程**：虚地址 → 查TLB → 命中直接得物理地址；不命中查页表并更新TLB
- **抖动**：频繁TLB未命中

#### 3. 虚地址→物理地址转换

```
虚地址 = [虚页号] | [页内偏移]
  ↓ 查页表
物理地址 = [物理页框号] | [页内偏移]  ← 偏移量不变！
```

### 五、易错点

- ❌ DRAM破坏性读出意味着数据丢了 → ✅ 读出后芯片内部会自动重写
- ❌ Cache行越大越好 → ✅ 太大增加缺失代价，太小增加缺失率
- ⚠️ 写回+写分配 vs 写直达+非写分配 → 这是两种典型组合

## 📗 操作系统 第3章 内存管理

### 一、内存管理概述

#### 1. 程序运行步骤

```
编译 → 链接（静态/装入时动态/运行时动态） → 装入（绝对/可重定位/运行时动态）
```

#### 2. 逻辑地址 vs 物理地址

- **逻辑地址**：CPU生成的地址（编译后确定）
- **物理地址**：内存单元的实际地址
- **MMU（内存管理单元）**：负责逻辑→物理的转换（含**重定位寄存器/基址寄存器**）

### 二、连续分配管理方式

| 方式 | 思想 | 特点 | 外部碎片 |
|------|------|------|----------|
| 单一连续 | 内存分系统区+用户区 | 简单，只用于单用户 | 有 |
| 固定分区 | 预划分固定大小分区 | 内部碎片严重 | 无 |
| 动态分区 | 按需分配，大小可变 | 外部碎片 → 需**紧凑** | 有 |

#### 动态分区分配算法

| 算法 | 思想 | 特点 |
|------|------|------|
| **首次适应(FF)** | 找到第一个够大的空闲块 | 简单快速，低地址产生碎片 |
| **最佳适应(BF)** | 找最接近大小的空闲块 | 产生最多小碎片 |
| **最坏适应(WF)** | 找最大的空闲块 | 减少小碎片 |
| **循环首次适应(NF)** | 从上次找到的位置继续 | 使空闲区分布均匀 |

### 三、分页存储管理 ⭐（核心考点）

#### 1. 基本概念

| 概念 | 说明 |
|------|------|
| **页(Page)** | 逻辑地址空间的固定大小块 |
| **页框/帧(Frame)** | 物理内存的固定大小块（与页等大） |
| **页表** | 记录每个页对应的物理页框号 |
| **页内偏移** | 逻辑地址低位，物理地址直接继承 |

#### 2. 地址变换 ⭐

```
逻辑地址 A → 页号 P = A / 页面大小, 页内偏移 W = A % 页面大小
查页表：物理块号 B = 页表[P].块号
物理地址 = B × 页面大小 + W
```

#### 3. TLB 与多级页表

| 技术 | 目的 | 原理 |
|------|------|------|
| **TLB（快表）** | 加速地址变换 | 缓存最近使用的页表项（命中→跳过访存） |
| **多级页表** | 节省页表空间 | 将页表再分页，不存在的次级页表不分配 |

> 🔥 **TLB命中时**：有效访存时间 = TLB访问时间 + 一次访存

#### 4. 访问内存次数分析（常考）

| 场景 | 访存次数 |
|------|----------|
| 无TLB、单级页表 | **2次**（页表+数据） |
| 无TLB、两级页表 | **3次**（一级+二级+数据） |
| TLB命中、单级页表 | **1次**（TLB命中直接访数据） |
| TLB未命中、单级页表 | **2次**（页表+数据；之后更新TLB） |

### 四、分段与段页式管理

| 方式 | 优势 | 劣势 |
|------|------|------|
| **分段** | 符合用户逻辑（代码段/数据段），便于共享保护 | 外部碎片，内存利用率低 |
| **段页式** | 兼有两家之长 | 三次访存（段表→页表→数据），复杂 |

### 五、虚拟内存管理 ⭐

#### 1. 核心概念

- **虚拟内存**：逻辑上扩充内存的容量，作业不必全部装入即可运行
- **基础**：局部性原理（时间局部性+空间局部性）
- **实现方式**：请求分页 / 请求分段

#### 2. 页面置换算法 ⭐（408高频考点）

| 算法 | 规则 | Belady异常 | 实现 |
|------|------|------------|------|
| **OPT** | 替换未来最久不用的 | 无 | 理论最优，不可实现 |
| **FIFO** | 先进先出 | **有**（唯一的产生者！） | 队列 |
| **LRU** | 替换最久未用的 | 无 | 栈/计数器，开销大 |
| **CLOCK(NRU)** | 循环扫描，访问位=0则淘汰 | 无 | 近似LRU，实用 |
| **改进CLOCK** | 优先淘汰(0,0)→(0,1)→(1,0)→(1,1) | 无 | 更优 |

> 🔥 **Belady异常**：给更多物理块，缺页率反而升高！只有FIFO会产生。

#### 3. 缺页率影响因素

- 页面大小：太大→浪费，太小→缺页频繁
- 物理块数：越多→缺页越低（FIFO不一定）
- 置换算法：LRU > CLOCK > FIFO
- 程序局部性：好→缺页少

#### 4. 抖动(Thrashing)与工作集

| 概念 | 含义 |
|------|------|
| **抖动** | 频繁缺页，CPU大量时间用于对换而非执行 |
| **工作集** | 某时间段内进程实际访问的页集合 |
| **防治** | 减少并发进程数；工作集模型；缺页频度控制 |

### 六、易错点

- ❌ 缺页中断属于外中断 → ✅ 缺页属于**内中断（异常）**
- ❌ 页面越大越好 → ✅ 页面过大会增加内部碎片和I/O开销
- ⚠️ 只有FIFO有Belady异常！LRU和CLOCK都没有
- ⚠️ 虚拟地址→物理地址，**页内偏移量不变**

## 📘 计组 第4章 指令系统

### 一、指令格式

#### 1. 指令结构

```
[操作码 OP] | [地址码 A1] | [地址码 A2] | ...
```

#### 2. 操作码设计

| 方式 | 特点 | 适用 |
|------|------|------|
| **定长操作码** | 所有指令操作码位数相同 | 指令数少、RISC风格 |
| **扩展操作码** | 操作码位数可变，短码给常用指令 | **408常考**，需会数可编码指令数 |
| **哈夫曼编码** | 最短码给最常用指令 | 理论最优 |

> 🔥 **扩展操作码公式**：若n位操作码，k种m位指令，则剩余可编码 $(2^n - k) \times 2^m$ 条更短指令。

#### 3. 地址码结构

| 指令类型 | 操作数来源 | 特点 |
|----------|-----------|------|
| 三地址 | OP A1, A2, A3 | A1←A2 OP A3，指令长 |
| 二地址 | OP A1, A2 | A1←A1 OP A2，最常用 |
| 一地址 | OP A | 隐含ACC，如 `ADD A` = ACC←ACC+A |
| 零地址 | OP | 操作数隐含（堆栈/空操作） |

### 二、寻址方式 ⭐（选择题必考）

#### 1. 10种寻址方式速查

| 寻址方式 | 操作数位置 | EA（有效地址） |
|----------|-----------|---------------|
| **立即寻址** | 指令中直接给出 | 无（操作数=指令中的立即数） |
| **直接寻址** | EA = 地址码 | EA = A |
| **间接寻址** | EA = 内存[A] | EA = (A) |
| **寄存器寻址** | 寄存器中 | 无（操作数=Rn） |
| **寄存器间接** | EA = 寄存器内容 | EA = (Rn) |
| **变址寻址** | EA = (IX) + A | EA = (IX) + A |
| **基址寻址** | EA = (BR) + A | EA = (BR) + A |
| **相对寻址** | EA = (PC) + A | EA = (PC) + A（多用于转移指令） |
| **堆栈寻址** | 栈顶 | 隐含SP |
| **复合寻址** | 如先变址再间接 | EA = ((IX) + A) |

#### 2. 变址 vs 基址（关键区分）

| 对比 | 变址寻址 | 基址寻址 |
|------|----------|----------|
| 寄存器 | 变址寄存器 IX | 基址寄存器 BR |
| 谁变？ | **指令地址码A不变，IX可变** | **BR不变，A可变** |
| 用途 | 数组访问（循环中IX自增） | 程序重定位（多道程序） |
| 谁编入？ | A是**形式地址**（数组首址） | BR是**基地址**，A是**偏移量** |

> 🔥 相对寻址中，(PC)是程序计数器当前值，A是补码偏移量（可正可负）。

### 三、CISC vs RISC ⭐

| 对比维度 | CISC（复杂指令集） | RISC（精简指令集） |
|----------|-------------------|-------------------|
| 指令数目 | 多 | 少（通常<100条） |
| 指令字长 | 可变 | **定长** |
| 寻址方式 | 多种 | 少（通常只有LOAD/STORE访存） |
| 执行时间 | 差异大 | **大多一个周期** |
| 控制方式 | **微程序控制** | **硬布线控制** |
| 寄存器数量 | 少 | 多（大量通用寄存器） |
| 编译器 | 简单 | 复杂（需优化编译） |
| 代表 | x86 | ARM、MIPS、RISC-V |

### 四、易错点

- ❌ 变址寻址是形式地址A在变 → ✅ 变址寄存器IX在变，A不变
- ❌ CISC用硬布线，RISC用微程序 → ✅ 恰好相反：CISC微程序，RISC硬布线
- ⚠️ 间接寻址访问内存1次以上；寄存器寻址不访存

## 📗 操作系统 第4章 文件管理

### 一、文件系统基础

#### 1. 文件逻辑结构

| 类型 | 结构 | 存取方式 |
|------|------|----------|
| 流式文件 | 无结构字节序列 | 顺序 |
| 记录式文件 | 定长/变长记录 | 顺序/随机 |

#### 2. 文件操作

| 操作 | 说明 |
|------|------|
| Create/Delete | 创建/删除文件 |
| Open/Close | 打开（建立FCB→内存）/关闭 |
| Read/Write | 读/写数据 |
| Seek | 定位文件指针 |

> 🔥 **打开文件**：将FCB（文件控制块）从磁盘读入内存；关闭则写回。

### 二、目录结构

| 结构 | 特点 | 问题 |
|------|------|------|
| 单级目录 | 全部文件一个目录 | 命名冲突 |
| 两级目录 | 主目录(MFD) + 用户目录(UFD) | 用户间不能共享 |
| **树形目录** | 多级层次，**现代OS主流** | 查找快，可重名 |
| 无环图目录 | 可共享同一文件 | 删除需引用计数 |

### 三、文件物理结构 ⭐

#### 1. 三种分配方式对比

| 方式 | 实现 | 优点 | 缺点 | 代表 |
|------|------|------|------|------|
| **连续分配** | 文件占连续磁盘块 | 简单，顺序访问快 | 外部碎片，需预知大小 | — |
| **隐式链接** | 每块含下一块指针 | 无碎片，可动态增长 | 只能顺序访问，指针占空间 | — |
| **显式链接(FAT)** | 链接指针集中存入FAT表 | FAT在内存→随机访问快 | FAT表本身占用空间 | FAT文件系统 |
| **索引分配** | 索引块存储所有块号 | 支持随机访问 | 索引块额外开销 | Unix/Linux inode |

#### 2. 索引分配进阶

| 变体 | 原理 |
|------|------|
| **单级索引** | 一个索引块指向所有数据块 |
| **多级索引** | 索引块指向更次级索引块 |
| **混合索引** | 直接块 + 一级间接 + 二级间接 + 三级间接（Unix inode方式） |

> 🔥 **Unix混合索引**：小文件用直接块（快速），大文件逐级间接（扩展容量）。408常考文件最大长度的计算。

### 四、文件存储空间管理

| 方法 | 原理 | 特点 |
|------|------|------|
| **空闲表法** | 连续空闲区表 | 类似动态分区 |
| **空闲链表法** | 空闲块串联成链 | 效率低 |
| **位示图法** | 1bit表示1块是否空闲 | **最常用**，适合向量运算 |
| **成组链接法** | 分组链接，最后一组首块存下一组信息 | Unix采用 |

> 🔥 **位示图计算**：字号 i = 块号 / 字长，位号 j = 块号 % 字长

### 五、文件共享与保护

| 概念 | 说明 |
|------|------|
| **硬链接** | 多个目录项指向**同一inode**，引用计数+1；删除一个不减到0则不释放 |
| **软链接(符号链接)** | 新建文件存目标路径；删除原文件则链接失效（类似快捷方式） |

> 🔥 **硬链接不能跨文件系统，不能链接目录；软链接可以。**

### 六、磁盘管理 ⭐

#### 1. 磁盘访问时间

$$T = T_s + T_r + T_t$$

| 分量 | 含义 |
|------|------|
| $T_s$（寻道时间） | 磁头移动到目标柱面（**占比最大**） |
| $T_r$（旋转延迟） | 扇区旋转到磁头下（平均 = 转一圈时间/2） |
| $T_t$（传输时间） | 实际读写数据的时间 |

#### 2. 磁盘调度算法（常考计算题）

| 算法 | 策略 | 特点 | 饥饿 |
|------|------|------|------|
| **FCFS** | 按请求顺序 | 公平但性能差 | 无 |
| **SSTF** | 最短寻道时间优先 | 性能较好 | **有**（远处请求可能饿死） |
| **SCAN（电梯）** | 单向移动到头再折返 | 较好 | 边缘磁道稍不利 |
| **C-SCAN** | 单向移动，到最远端直接跳到最内端 | 更公平（循环） | 改善边缘 |
| **LOOK** | SCAN变体：到最远请求即折返 | 实际采用（Linux） | — |
| **C-LOOK** | C-SCAN变体：到两端请求即跳回 | 实用 | — |

### 七、易错点

- ❌ 文件打开时就把全部数据读入内存 → ✅ 只是FCB进内存，数据仍在外存
- ❌ 硬链接是复制一份文件 → ✅ 硬链接是**别名**，指向同一inode
- ⚠️ 磁盘访问时间中，寻道时间占主导，所以SSTF主要优化寻道
- ⚠️ 成组链接法中，空闲盘块号栈放在每组最后一个空闲块中

## 📘 计组 第5章 中央处理器(CPU)

### 一、CPU 基本结构

```
CPU
├── 运算器（数据通路）
│   ├── ALU（算术逻辑单元）
│   ├── ACC（累加器）
│   ├── MQ（乘商寄存器）
│   ├── DR（数据寄存器）
│   └── PSW/FLAGS（状态寄存器：ZF/CF/OF/SF等标志位）
└── 控制器
    ├── PC（程序计数器）
    ├── IR（指令寄存器）
    ├── ID（指令译码器）
    ├── MAR（存储器地址寄存器）
    ├── MDR（存储器数据寄存器）
    └── 时序产生器 + 微操作信号发生器
```

### 二、指令执行过程

#### 四个周期

| 周期 | 操作 | 访存？ |
|------|------|--------|
| **取指周期(FE)** | PC→MAR→内存→MDR→IR, PC+1 | 是 |
| **间址周期(IND)** | 取操作数有效地址 | 可能 |
| **执行周期(EX)** | 执行操作 | 可能 |
| **中断周期(INT)** | 保存断点，关中断，转中断服务 | 是（保存断点） |

> 🔥 **间址周期**只在间接寻址时存在；**中断周期**只在有中断请求时存在。

### 三、数据通路与控制方式

#### 1. 数据通路结构

| 结构 | 特点 |
|------|------|
| 单总线 | 简单但冲突多，一次一个传送 |
| 双总线 | 可并行两个传送 |
| 三总线 | 最多并行，效率最高 |

#### 2. 两种控制器 ⭐

| 对比 | 硬布线控制器 | 微程序控制器 |
|------|------------|------------|
| 实现方式 | 组合逻辑电路 | 微程序（存储在控制存储器） |
| 速度 | **快** | 慢（多一次控存读取） |
| 灵活性 | 差（指令集固定即电路固定） | **好**（改微程序即可） |
| 规整性 | 不规整 | 规整 |
| 适用 | **RISC** | **CISC** |
| 408考点 | 理解为主 | 微指令格式、微地址形成 |

#### 3. 微程序关键概念

| 概念 | 说明 |
|------|------|
| 微指令 | 一条微指令产生一组微命令，控制一个节拍的微操作 |
| 微程序 | 若干微指令的有序集合，实现一条机器指令 |
| 控制存储器(CM) | 存放微程序，通常用ROM |
| 微地址形成 | 下址字段法 / 断定法（根据操作码+测试条件） |

> 🔥 **微指令格式**：水平型（并行控制，快但长）vs 垂直型（类似机器指令，慢但短）

### 四、指令流水线 ⭐（重中之重）

#### 1. 经典5段流水

```
IF → ID → EX → MEM → WB
取指   译码   执行   访存   写回
```

#### 2. 流水线性能公式

| 指标 | 公式 |
|------|------|
| **吞吐率(TP)** | $TP = \frac{n}{(k+n-1)\Delta t}$（n→∞时 TP→1/Δt） |
| **加速比(S)** | $S = \frac{k \cdot n \cdot \Delta t}{(k+n-1)\Delta t}$（n→∞时 S→k） |
| **效率(E)** | $E = \frac{k \cdot n}{k \cdot (k+n-1)}$（n→∞时 E→1） |

其中 k=流水段数，n=指令数，Δt=时钟周期。

#### 3. 流水线冒险（Hazard）⭐

| 冒险类型 | 原因 | 解决方案 |
|----------|------|----------|
| **结构冒险** | 硬件资源冲突（如IF和MEM同时访存） | 分离指令Cache和数据Cache |
| **数据冒险** | 指令间数据依赖 | ①**转发/旁路** ②插入气泡(stall) ③编译优化 |
| **控制冒险** | 转移指令导致PC变化 | ①**分支预测**（静态/动态）②延迟分支 ③提前判断 |

> 🔥 **数据冒险三种**：RAW（读后写，最常见）、WAR、WAW；RAW必须等待，WAR/WAW在乱序执行中才出现。

#### 4. 流水线优化技术

| 技术 | 思想 |
|------|------|
| **转发(Forwarding)** | ALU结果直接反馈给EX段输入，不等到WB写回 |
| **静态分支预测** | 总是预测不跳转 / 总是预测跳转 |
| **动态分支预测** | 根据历史记录（如2位预测器）预测方向 |
| **超标量** | 每个时钟周期**发射多条指令**（多套功能部件） |
| **超流水线** | 将流水段进一步细分，时钟频率更高 |
| **超长指令字(VLIW)** | 编译器静态调度多条并行指令 |

### 五、易错点

- ❌ 结构冒险只发生在单总线CPU → ✅ 即使Harvard结构，多指令同时访问同一部件也会结构冒险
- ❌ 插入气泡和转发解决同样的数据冒险 → ✅ 转发消除大部分数据冒险；转发不了才插气泡
- ⚠️ 流水线中PC+1不是在IF段末尾，而是IF段开始就需要（取下一条指令地址）

## 📗 操作系统 第5章 I/O管理

### 一、I/O管理概述

#### I/O设备分类

| 分类维度 | 类型 |
|----------|------|
| 传输速率 | 低速（键盘/鼠标）、中速（打印机）、高速（磁盘） |
| 信息交换单位 | **块设备**（磁盘，以块为单位）、**字符设备**（键盘，以字节为单位） |
| 共享属性 | 独占设备、共享设备、虚拟设备 |

### 二、I/O软件层次结构

```
用户层I/O软件（库函数如printf/scanf）
        ↓
设备独立性软件（统一接口、命名、保护、缓冲、分配）
        ↓
设备驱动程序（与硬件打交道，每类设备一个驱动）
        ↓
中断处理程序（处理I/O完成中断）
        ↓
硬件（I/O设备 + 控制器）
```

> 🔥 **设备独立性**：用户程序用逻辑设备名，OS映射到物理设备。如`/dev/sda`不随硬件更换而需改代码。

### 三、SPOOLing 技术（假脱机）⭐

| 概念 | 说明 |
|------|------|
| **核心思想** | 用磁盘模拟独占设备，将独占设备变为共享设备 |
| 输入井/输出井 | 磁盘上暂存输入/输出数据的区域 |
| 输入进程/输出进程 | 负责数据在井和设备间传送（**守护进程**） |
| **典型应用** | 共享打印机（多用户同时"打印"→数据入输出井→排队输出） |

> 🔥 SPOOLing将**独占设备虚拟为共享设备**，体现OS的"虚拟"特征。

### 四、缓冲区管理 ⭐

#### 1. 为什么要缓冲？

- 缓解CPU与I/O设备**速度不匹配**
- 减少设备**中断频率**
- 提高CPU与I/O设备的**并行度**

#### 2. 缓冲类型对比

| 类型 | 结构 | 并行处理能力 |
|------|------|------------|
| **单缓冲** | 1个缓冲区 | CPU处理 + I/O输入 交替（时间 ≈ max(C, T) + M） |
| **双缓冲** | 2个缓冲区交替 | CPU和I/O可**同时**工作（时间 ≈ max(C, T)） |
| **循环缓冲** | 多个缓冲区环形排列 | 类似双缓冲，适合大量数据 |
| **缓冲池** | 系统公用缓冲区集合 | 三种队列：空缓冲/输入/输出队列 |

其中 C=CPU处理时间，T=I/O传输时间，M=数据搬移时间。

#### 3. I/O控制方式回顾（计组+OS交叉）

| 方式 | CPU干预 | 数据传送 | 适用 |
|------|---------|----------|------|
| 程序直接控制 | CPU全程控制 | CPU | 简单慢速设备 |
| 中断方式 | 仅开始和结束时干预 | CPU | 中低速设备 |
| DMA | 仅开始和结束时干预 | **DMA控制器** | 高速块设备（磁盘） |
| 通道 | 最少干预 | **通道处理器** | 大型机多设备 |

### 五、易错点

- ❌ SPOOLing是真正实现了设备并行 → ✅ SPOOLing是逻辑上的"并行"（假脱机），物理上串行
- ❌ 双缓冲一定比单缓冲快一倍 → ✅ 取决于C和T的相对大小：T>C时有效，C≥T时差异不大
- ⚠️ DMA传送单位是**数据块**；中断方式传送单位是**字节/字**

## 📘 计组 第6章 总线

### 一、总线概述

#### 1. 总线分类

| 按连接部件 | 说明 |
|-----------|------|
| **片内总线** | CPU芯片内部（寄存器间） |
| **系统总线** | CPU、内存、I/O接口之间（**408重点**） |
| **通信总线** | 计算机系统之间（如USB） |

#### 2. 系统总线的三类线

| 类型 | 方向 | 功能 |
|------|------|------|
| 数据总线 | **双向** | 传送数据 |
| 地址总线 | **单向**（CPU→设备） | 传送地址 |
| 控制总线 | 每根线单向（有出有入） | 传送控制信号（读/写/中断/时钟等） |

#### 3. 总线性能指标

| 指标 | 含义 |
|------|------|
| 总线宽度 | 数据线条数（如64位） |
| 总线频率 | 每秒传输次数 |
| **总线带宽** | 宽度 × 频率（如 64bit × 100MHz = 800MB/s） |
| 总线复用 | 地址线和数据线分时共享（减少引脚） |

### 二、总线仲裁 ⭐

| 仲裁方式 | 机制 | 特点 | 优先级 |
|----------|------|------|--------|
| **链式查询** | 总线授权信号串行传递 | 结构简单，对故障敏感 | 距仲裁器越近越高 |
| **计数器定时查询** | 计数器轮询设备号 | 较公平，可改优先级 | 可编程 |
| **独立请求** | 每设备独立请求线 | 响应快，线多 | 仲裁器决定 |
| **分布仲裁** | 无中央仲裁器，设备自裁决 | 可靠性高 | 各设备协商 |

### 三、总线操作与定时

#### 同步 vs 异步

| 对比 | 同步定时 | 异步定时 |
|------|----------|----------|
| 控制方式 | 统一时钟信号 | **握手信号**（请求/应答） |
| 速度 | 快 | 较慢（握手开销） |
| 灵活性 | 差（所有设备同频） | **好**（快慢设备可共存） |
| 可靠性 | 差（时钟偏斜问题） | 好 |

> 🔥 **半同步通信**：结合两者——统一时钟 + 插入等待信号（Wait信号），兼顾速度和灵活性。

### 四、易错点

- ❌ 数据总线永远是双向 → ✅ 系统总线中数据总线双向，但某些专用总线可能单向
- ⚠️ 链式查询的优先级取决于**物理位置**（离仲裁器越近越高）
- ⚠️ 异步定时有三种握手方式：不互锁、半互锁、全互锁

### 一、I/O接口

| 功能 | 说明 |
|------|------|
| 数据缓冲 | 匹配速度差异 |
| 信号转换 | 电平/格式转换 |
| 地址译码 | 识别本设备 |
| 中断/DMA控制逻辑 | 配合中断/DMA使用 |

#### I/O端口编址

| 方式 | 特点 | 代表 |
|------|------|------|
| **统一编址（内存映射I/O）** | I/O端口与内存统一编址，用访存指令访问 | ARM、MIPS |
| **独立编址（I/O映射I/O）** | I/O端口独立编址，需专用I/O指令 | x86（IN/OUT指令） |

### 二、中断系统 ⭐

#### 1. 中断优先级与屏蔽

| 概念 | 说明 |
|------|------|
| **中断优先级** | 多个中断同时请求时，响应优先级高的 |
| **中断屏蔽** | 通过屏蔽字禁止某些中断（可在中断服务程序中设置） |
| **多重中断** | 高优先级中断可打断低优先级中断服务程序 |

> 🔥 **中断屏蔽触发器**：=1时屏蔽**本级及更低级**中断（不是只屏蔽本级）

#### 2. 中断响应条件

1. 中断源有请求
2. CPU允许中断（IF=1）
3. **一条指令执行结束**时才响应（不是任意时刻！）

#### 3. 中断隐指令（硬件自动完成）

1. **关中断**（IF←0）
2. **保存断点**（PC→堆栈）
3. **引出中断服务程序**（中断向量→PC）

### 三、DMA方式 ⭐

#### 1. DMA vs 中断

| 对比 | 中断 | DMA |
|------|------|-----|
| 数据传送单位 | 字/字节 | **数据块** |
| 数据传送方向 | 外设↔CPU↔内存 | 外设↔内存（不经过CPU） |
| CPU干预 | 每个数据传输都有 | 仅预处理和后处理 |
| 请求响应时机 | 指令执行结束 | **任意时刻可响应**（只需总线） |
| 优先级 | 低于DMA | **高于中断** |

#### 2. DMA传送方式

| 方式 | 说明 |
|------|------|
| **停止CPU访问** | DMA期间CPU暂停（效率低） |
| **周期挪用** | DMA窃取一个总线周期 | 
| **交替访问** | CPU和DMA交替使用总线 |

> 🔥 周期挪用是最常用的方式——DMA控制器"偷"一个总线周期来完成一次数据传送。

#### 3. DMA工作过程

```
① 预处理：CPU初始化DMA（源/目的地址、传送字数、方向）
② 数据传送：DMA控制器控制总线，完成块传送
③ 后处理：传送结束，DMA向CPU发中断请求
```

### 四、易错点

- ❌ DMA比中断优先级低 → ✅ DMA优先级**高于**中断（需要快速响应）
- ❌ 中断只能在指令边界响应 → ✅ 对中断如此；但DMA可在任意总线周期响应
- ⚠️ 中断隐指令是**硬件完成**的，不是程序员编写的

## 🔗 两科交叉知识点对比整合

### 1. 存储体系：Cache ↔ TLB ↔ 页表

| 对比维度 | Cache | TLB | 页表 |
|----------|-------|-----|------|
| 作用 | 缓存**数据/指令** | 缓存**页表项** | 记录虚页→物理页映射 |
| 所在位置 | CPU内部 | CPU内部 | **主存**中 |
| 所属课程 | 计组为主 | **两科都考** | OS为主 |
| 实现方式 | SRAM（硬件） | 相联存储器（硬件） | 普通内存（软件管理） |
| 映射方式 | 直接/全相联/组相联 | 全相联为主 | 页号→页框号索引 |
| 替换算法 | LRU/FIFO/随机 | LRU为主 | — |
| 命中/缺失 | Cache命中的访存时间为T_c | TLB命中省去一次查页表的访存 | — |

### 2. 局部性原理的两种应用

| 局部性类型 | 含义 | 计组应用 | OS应用 |
|-----------|------|---------|--------|
| **时间局部性** | 刚访问过的数据可能再次被访问 | Cache保留最近访问的块 | 页表项在TLB中缓存 |
| **空间局部性** | 附近的数据可能即将被访问 | Cache预取相邻块 | 预调页策略 / 大页面 |

### 3. 虚拟存储：计组 vs OS 视角

| 层面 | 计组视角 | OS视角 |
|------|---------|--------|
| 关注点 | 硬件实现（TLB、页表基址寄存器、MMU） | 软件管理（页表维护、缺页处理、置换算法） |
| 核心问题 | 虚地址如何高效转换为物理地址？ | 如何减少缺页、如何选择置换页？ |
| 关键技术 | TLB、多级页表硬件支持 | 请求分页、页面置换算法、工作集模型 |

### 4. Cache 替换算法 ↔ 页面置换算法

| 计组（Cache） | OS（虚拟内存） | 对应关系 |
|---------------|---------------|----------|
| FIFO | FIFO | 完全一致；可能产生Belady异常 |
| LRU | LRU | 完全一致；无Belady异常 |
| 随机 | — | Cache独有的简单方案 |
| — | CLOCK / 改进CLOCK | **页面置换特有**，近似LRU |
| OPT | OPT | 完全一致；理论最优，不可实现 |

### 5. 中断系统：计组 vs OS

| 层面 | 计组视角 | OS视角 |
|------|---------|--------|
| 关注点 | 硬件机制（中断隐指令、中断向量、优先级电路） | 软件处理（中断服务程序、上下文保存与恢复） |
| 分类 | 可屏蔽/不可屏蔽；内部/外部 | 中断(外中断) vs 异常(内中断) |
| DMA优先级 | DMA请求高于中断 | — |
| 响应时机 | 每条指令结束后 | 缺页可发生在指令执行**过程中** |

### 6. I/O控制方式：从计组到OS的递进

```
程序直接控制 → 中断方式 → DMA方式 → 通道方式
  (计组+OS)     (计组+OS)   (计组为主)   (OS为主)
   CPU全程       CPU每次     DMA控制器    通道独立
   参与传送       参与传送     控制传送      控制传送
```

### 7. 命名的对应关系

| 计组术语 | OS术语 | 含义 |
|----------|--------|------|
| 虚页号 | 逻辑页号 | 虚拟地址的页索引 |
| 物理页框号 / 实页号 | 物理块号 / 页框号 | 物理内存的块索引 |
| 快表 TLB | TLB | 同一个东西 |
| 控制存储器(CM) | — | 微程序专用，OS不涉及 |
| 存储保护 | 内存保护 | 上下界/基址限长 → 页表保护位 |
