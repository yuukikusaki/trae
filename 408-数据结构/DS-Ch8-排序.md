## 8.1 排序基本概念

**排序**：将无序序列重新排列成按关键字有序的序列。

- **稳定性**：若 $k_i = k_j$ 且排序前 $R_i$ 在 $R_j$ 之前，排序后 $R_i$ 仍在 $R_j$ 之前，则称该排序算法是**稳定的**。
- **内部排序**：排序期间元素全部存放在内存中。
- **外部排序**：排序期间元素无法全部同时在内存中，需要在内、外存之间移动。

## 8.2 插入排序

### 8.2.1 直接插入排序

**思想**：将待排序元素逐个插入到已排序序列的合适位置。初始时认为第 1 个元素已排序。

```c
//==408考点== 直接插入排序
void InsertSort(int A[], int n) {
    int i, j, temp;
    for (i = 1; i < n; i++) {          // 依次将 A[1]~A[n-1] 插入
        if (A[i] < A[i - 1]) {          // 若当前元素小于前驱，需插入
            temp = A[i];                // 暂存待插入元素
            for (j = i - 1; j >= 0 && A[j] > temp; j--)
                A[j + 1] = A[j];        // 大于 temp 的元素后移
            A[j + 1] = temp;            // 插入到正确位置
        }
    }
}
```

**复杂度分析：**

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n)$ | 序列已有序，每趟只比较 1 次，无需移动 |
| 最坏 | $O(n^2)$ | 序列逆序，比较和移动次数均达最大 |
| 平均 | $O(n^2)$ | |
| 空间 | $O(1)$ | 原地排序，仅需常数辅助空间 |
| **稳定性** | **稳定** | 相等元素不会跨越插入 |

**408 技巧**：
- 比较次数：最好 $n-1$，最坏 $\frac{n(n-1)}{2}$
- 移动次数：最好 $0$，最坏 $\frac{n(n-1)}{2}$
- 适合基本有序、数据量小的序列

---

### 8.2.2 折半插入排序

**思想**：在直接插入排序基础上，用二分查找确定插入位置，减少比较次数。移动次数不变。

```c
//==408考点== 折半插入排序
void BinaryInsertSort(int A[], int n) {
    int i, j, low, high, mid, temp;
    for (i = 1; i < n; i++) {
        temp = A[i];
        low = 0; high = i - 1;
        //==408考点== 二分查找插入位置
        while (low <= high) {
            mid = (low + high) / 2;
            if (A[mid] > temp)
                high = mid - 1;
            else
                low = mid + 1;           // 为保证稳定性，相等时也往后找
        }
        // 插入位置为 high+1 (即 low)
        for (j = i - 1; j >= low; j--)
            A[j + 1] = A[j];
        A[low] = temp;
    }
}
```

**复杂度分析：**

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n\log n)$ | 比较次数减少为 $O(n\log n)$，但移动仍 $O(n)$ |
| 最坏 | $O(n^2)$ | 移动次数仍为 $O(n^2)$ |
| 平均 | $O(n^2)$ | 总复杂度由移动次数主导 |
| 空间 | $O(1)$ | |
| **稳定性** | **稳定** | `A[mid] > temp` 时往前找，保证稳定性 |

**408 技巧**：折半插入只减少了比较次数（$O(n\log n)$），移动次数仍是 $O(n^2)$，因此总时间复杂度仍为 $O(n^2)$。

### 8.2.3 希尔排序

**思想**：将序列按增量 gap 分成若干子序列，分别进行直接插入排序；然后逐步缩小 gap，直至 gap=1 完成最终排序。

```c
//==408考点== 希尔排序
void ShellSort(int A[], int n) {
    int gap, i, j, temp;
    //==408考点== gap 序列：常考 gap = n/2, n/4, ..., 1
    for (gap = n / 2; gap > 0; gap /= 2) {
        // 对每个子序列进行直接插入排序
        for (i = gap; i < n; i++) {
            if (A[i] < A[i - gap]) {
                temp = A[i];
                for (j = i - gap; j >= 0 && A[j] > temp; j -= gap)
                    A[j + gap] = A[j];
                A[j + gap] = temp;
            }
        }
    }
}
```

**复杂度分析：**

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n)$ / $O(n\log n)$ | 取决于 gap 序列 |
| 最坏 | $O(n^2)$ | gap=1 时为直接插入排序 |
| 平均 | $O(n^{1.3})$ ~ $O(n^{1.5})$ | 经验值，考试用 $O(n^{1.3})$ |
| 空间 | $O(1)$ | |
| **稳定性** | **不稳定** | 相同元素可能被分到不同子序列而交换 |

**408 技巧**：
- gap 序列常考 `n/2, n/4, ..., 1`（Shell 原始增量）
- 希尔排序是插入排序的改进，最后一趟 gap=1 等价于直接插入排序
- 不稳定原因：分组跳跃式移动

## 8.3 交换排序

### 8.3.1 冒泡排序

**思想**：从后往前（或从前往后）两两比较相邻元素，若逆序则交换，每趟将最小（或最大）元素"冒泡"到正确位置。

```c
//==408考点== 冒泡排序（从后往前，将小元素冒到前面）
void BubbleSort(int A[], int n) {
    int i, j, temp;
    bool flag;                          //==408考点== 交换标志，用于提前终止
    for (i = 0; i < n - 1; i++) {
        flag = false;
        for (j = n - 1; j > i; j--) {   // 从后往前比较
            if (A[j - 1] > A[j]) {       // 若逆序
                temp = A[j];
                A[j] = A[j - 1];
                A[j - 1] = temp;
                flag = true;
            }
        }
        if (!flag) break;                // 本趟无交换，已有序
    }
}
```

**复杂度分析：**

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n)$ | 已有序，一趟后 flag=false 直接结束 |
| 最坏 | $O(n^2)$ | 逆序 |
| 平均 | $O(n^2)$ | |
| 空间 | $O(1)$ | |
| **稳定性** | **稳定** | `>` 而非 `>=`，相等不交换 |

**408 技巧**：
- 每趟确定一个元素的最终位置（最大或最小）
- 使用 flag 标志实现最好情况 $O(n)$
- 与快排区分：冒泡每趟产生一个全局有序元素

### 8.3.2 快速排序

**思想**（分治法）：
1. 选取枢轴 pivot，将序列划分为两部分：左边 $\le$ pivot，右边 $\ge$ pivot
2. 递归地对左右子序列进行快速排序

#### Partition 写法一：左右指针法（Hoare 变体）

```c
//==408考点== 快速排序 - 左右指针 Partition（王道/天勤主流写法）
int Partition_LR(int A[], int low, int high) {
    int pivot = A[low];                 //==408考点== 选第一个元素为枢轴
    while (low < high) {
        while (low < high && A[high] >= pivot) high--;  // 从右找小于 pivot 的
        A[low] = A[high];               // 移到左边
        while (low < high && A[low] <= pivot) low++;    // 从左找大于 pivot 的
        A[low] = A[high];               // 移到右边
    }
    A[low] = pivot;                     // 枢轴归位
    return low;                         // 返回枢轴最终位置
}

void QuickSort_LR(int A[], int low, int high) {
    if (low < high) {
        int pivotPos = Partition_LR(A, low, high); //==408考点== 划分
        QuickSort_LR(A, low, pivotPos - 1);         // 递归左子表
        QuickSort_LR(A, pivotPos + 1, high);        // 递归右子表
    }
}
```

#### Partition 写法二：前后指针法

```c
//==408考点== 快速排序 - 前后指针 Partition（也可用于链表排序）
int Partition_FrontBack(int A[], int low, int high) {
    int pivot = A[high];                // 选最后一个元素为枢轴
    int i = low - 1;                    // i 指向小于 pivot 区域的最后一个元素
    int j, temp;
    for (j = low; j < high; j++) {
        if (A[j] <= pivot) {            // 当前元素 <= pivot，放入左侧区域
            i++;
            temp = A[i]; A[i] = A[j]; A[j] = temp;
        }
    }
    // 将 pivot 放到正确位置
    temp = A[i + 1]; A[i + 1] = A[high]; A[high] = temp;
    return i + 1;
}

void QuickSort_FB(int A[], int low, int high) {
    if (low < high) {
        int pivotPos = Partition_FrontBack(A, low, high);
        QuickSort_FB(A, low, pivotPos - 1);
        QuickSort_FB(A, pivotPos + 1, high);
    }
}
```

**复杂度分析：**

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n\log n)$ | 每次划分均匀，递归树平衡 |
| 最坏 | $O(n^2)$ | 序列已有序或逆序，递归树退化为链 |
| 平均 | $O(n\log n)$ | 接近最好情况 |
| 空间 | $O(\log n)$ | 递归栈深度 |
| **稳定性** | **不稳定** | 划分时交换会破坏相对顺序 |

**408 易错点**：
- 快排的空间复杂度是 **$O(\log n)$（递归栈）**，不是 $O(1)$。每次递归调用需要保存现场参数。
- 最坏情况下栈深度为 $O(n)$。
- 快排每趟确定**一个**元素（pivot）的最终位置。
- 优化：三数取中选 pivot、小规模时切换为插入排序。

## 8.4 选择排序

### 8.4.1 简单选择排序

**思想**：每趟从待排序元素中选出最小（或最大）的，放到已排序序列末尾。

```c
//==408考点== 简单选择排序
void SelectSort(int A[], int n) {
    int i, j, minIdx, temp;
    for (i = 0; i < n - 1; i++) {
        minIdx = i;
        for (j = i + 1; j < n; j++) {
            if (A[j] < A[minIdx])
                minIdx = j;
        }
        if (minIdx != i) {
            temp = A[i]; A[i] = A[minIdx]; A[minIdx] = temp;
        }
    }
}
```

**复杂度分析：**

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n^2)$ | 始终需要 $\frac{n(n-1)}{2}$ 次比较 |
| 最坏 | $O(n^2)$ | |
| 平均 | $O(n^2)$ | |
| 空间 | $O(1)$ | |
| **稳定性** | **不稳定** | 交换可能跨越多个相等元素 |

**408 技巧**：
- 比较次数固定为 $\frac{n(n-1)}{2}$，与初始序列无关
- 移动次数：最好 $0$，最坏 $3(n-1)$
- 每趟确定一个元素的最终位置

### 8.4.2 堆排序

**思想**：利用大根堆（升序）或小根堆（降序）进行排序。
1. 建堆：将无序序列建成大根堆
2. 交换+调整：将堆顶与末尾交换，重新调整为新堆，重复

```c
//==408考点== 堆调整（大根堆下沉）
// 将以 k 为根的子树调整为大根堆，n 为堆元素总数
void HeadAdjust(int A[], int k, int n) {
    int rootVal = A[k];                 // 暂存根结点值
    int i;
    //==408考点== 沿较大的孩子结点向下筛选
    for (i = 2 * k + 1; i < n; i = 2 * i + 1) { // i 初值为左孩子
        // 选择较大的孩子
        if (i + 1 < n && A[i] < A[i + 1])
            i++;                        // i 指向右孩子
        if (rootVal >= A[i]) break;     // 已满足大根堆性质
        A[k] = A[i];                    // 将较大孩子上调
        k = i;                          // 修改 k 继续向下调整
    }
    A[k] = rootVal;                     // 放入最终位置
}

//==408考点== 建堆（从最后一个非叶结点开始）
void BuildMaxHeap(int A[], int n) {
    //==408考点== 最后一个非叶结点下标为 n/2 - 1（数组从 0 开始）
    for (int i = n / 2 - 1; i >= 0; i--)
        HeadAdjust(A, i, n);
}

//==408考点== 堆排序
void HeapSort(int A[], int n) {
    BuildMaxHeap(A, n);                 // O(n) 建堆
    int temp;
    for (int i = n - 1; i > 0; i--) {
        // 交换堆顶与末尾
        temp = A[0]; A[0] = A[i]; A[i] = temp;
        HeadAdjust(A, 0, i);            // 对剩余元素重新调整，O(log n)
    }
}
```

**复杂度分析：**

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n\log n)$ | |
| 最坏 | $O(n\log n)$ | |
| 平均 | $O(n\log n)$ | |
| 空间 | $O(1)$ | 原地排序 |
| **稳定性** | **不稳定** | 建堆和调整时交换会破坏相对顺序 |

**408 技巧**：
- 建堆复杂度：$O(n)$（不是 $O(n\log n)$！）
- 每趟调整复杂度：$O(\log n)$
- 总复杂度：$O(n\log n)$
- **最后一个非叶结点下标**：$\lfloor n/2 \rfloor - 1$（0-based 数组）或 $\lfloor n/2 \rfloor$（1-based）
- 堆排序适合**大数据量**的排序

## 8.5 归并排序（二路归并）

**思想**（分治法）：
1. 将序列递归地分成两个子序列，直到子序列长度为 1
2. 将两个有序子序列合并成一个有序序列

```c
//==408考点== 二路归并排序

// 辅助数组，大小至少为 n
int *B = NULL;  // 全局或通过参数传入

//==408考点== 合并两个有序序列：A[low..mid] 和 A[mid+1..high]
void Merge(int A[], int low, int mid, int high) {
    int i, j, k;
    // 将 A 中元素复制到辅助数组 B
    for (k = low; k <= high; k++)
        B[k] = A[k];
    //==408考点== 双指针合并
    for (i = low, j = mid + 1, k = low; i <= mid && j <= high; k++) {
        if (B[i] <= B[j])               // <= 保证稳定性
            A[k] = B[i++];
        else
            A[k] = B[j++];
    }
    // 处理剩余元素
    while (i <= mid) A[k++] = B[i++];
    while (j <= high) A[k++] = B[j++];
}

//==408考点== 递归归并排序
void MergeSort(int A[], int low, int high) {
    if (low < high) {
        int mid = (low + high) / 2;         // 从中间划分
        MergeSort(A, low, mid);             // 递归左半
        MergeSort(A, mid + 1, high);        // 递归右半
        Merge(A, low, mid, high);           // 合并
    }
}
```

**复杂度分析：**

| 情况 | 时间复杂度 | 说明 |
|------|-----------|------|
| 最好 | $O(n\log n)$ | |
| 最坏 | $O(n\log n)$ | |
| 平均 | $O(n\log n)$ | |
| 空间 | **$O(n)$** | 需要辅助数组 B[n] |
| **稳定性** | **稳定** | `Merge()` 中 `<=` 保证相等时左半先入 |

**408 技巧**：
- 归并排序的比较次数与初始序列无关
- 归并趟数：$\lceil \log_2 n \rceil$
- 每趟归并复杂度：$O(n)$
- 空间复杂度 $O(n)$ 是排序算法中的"另类"，大多数内部排序是 $O(1)$

## 8.6 基数排序

**思想**：不基于比较，而是基于关键字的各位进行分配和收集。多关键字排序思想：**最高位优先（MSD）**或**最低位优先（LSD）**。

**演示（LSD，以十进制整数为例）**：

```
初始序列: 278, 109, 063, 930, 589, 184, 505, 269, 008, 083

第1趟（按个位分配）：
  桶0: 930
  桶3: 063, 083
  桶4: 184
  桶5: 505
  桶8: 278, 008
  桶9: 109, 589, 269
收集: 930, 063, 083, 184, 505, 278, 008, 109, 589, 269

第2趟（按十位分配）：
  桶0: 505, 008, 109
  桶3: 930
  桶6: 063, 269
  桶7: 278
  桶8: 083, 184, 589
收集: 505, 008, 109, 930, 063, 269, 278, 083, 184, 589

第3趟（按百位分配）：
  桶0: 008, 063, 083
  桶1: 109, 184
  桶2: 269, 278
  桶5: 505, 589
  桶9: 930
收集: 008, 063, 083, 109, 184, 269, 278, 505, 589, 930
```

**关键参数：**
- 设 $n$ 个记录，每个关键字含 $d$ 个分量（d 趟分配收集），每个分量有 $r$ 种取值（r 个队列）
- 空间复杂度：$O(r)$（需要 r 个队列）
- 时间复杂度：$O(d(n+r))$
- **稳定性**：**稳定**（按位分配收集，不破坏同桶内的相对顺序）

**408 技巧**：基数排序适用于关键字取值范围有限且每位取值较少的情况（如整数、日期、字符串），不适合实数排序。

## 8.8 408 易错点总结

### 1. 快速排序的栈空间是 $O(\log n)$ 不是 $O(1)$

> **高频考点**。快排是递归实现的，递归需要系统栈保存每层的参数和返回地址。虽然快排是"原地"完成排序（不额外申请数组），但**递归栈深度**需要空间。最坏情况下递归树退化为链，栈深度达 $O(n)$。

```c
// 每次递归调用在系统栈中保存 (low, high, 返回地址...)
QuickSort(A, low, pivotPos - 1);  // 左递归
QuickSort(A, pivotPos + 1, high); // 右递归
```

### 2. 堆排序不稳定

> 在进行堆调整时，元素在数组中跳跃式交换（父子交换），可能跨越多个值相等的元素，从而改变它们的相对次序。

**反例**：序列 `[2, 2, 1]` 建大根堆后变成 `[2, 2, 1]`，第一次交换堆顶和末尾后变成 `[1, 2, 2]`，两个 2 的相对顺序改变了。

### 3. 希尔排序不稳定

> 希尔排序按增量分组进行插入排序。相同关键字可能被分到不同子序列中，在各自的子序列中移动，最终破坏了原来的相对顺序。

### 4. 归并排序需要 $O(n)$ 辅助空间

> 归并排序不是原地排序算法。`Merge()` 函数需要一个大小为 $n$ 的辅助数组来暂存待合并的数据。这是 $O(n\log n)$ 排序算法中唯一需要额外 $O(n)$ 空间的。

### 5. 关于"每趟是否确定最终位置"

| 算法 | 每趟确定最终位置 |
|------|-----------------|
| 冒泡排序 | 是（1 个） |
| 快速排序 | 是（1 个，pivot） |
| 简单选择排序 | 是（1 个） |
| 堆排序 | 是（1 个，交换后的堆顶） |
| 插入排序 | 否 |
| 希尔排序 | 否 |
| 归并排序 | 否 |
| 基数排序 | 否（各趟只确定某一位） |

### 6. 建堆复杂度是 $O(n)$ 不是 $O(n\log n)$

> 虽然调用 $n/2$ 次 `HeadAdjust`（每次 $O(\log n)$），但每个结点调整的高度不同：越靠近底层调整高度越低、结点数越多，总复杂度为 $O(n)$。

## 8.9 算法选择策略（408 场景）

| 场景 | 推荐算法 | 理由 |
|------|---------|------|
| $n$ 较小（$n \le 50$）| 直接插入 / 简单选择 | 常数因子小 |
| $n$ 较大 | 快排 / 堆排 / 归并 | $O(n\log n)$ |
| 基本有序 | 直接插入 / 冒泡 | 可达 $O(n)$ |
| 要求稳定 | 归并 / 插入 / 冒泡 | 稳定排序 |
| 只关心前 $k$ 个 | 堆排序 | 部分排序 |
| 关键字取值范围小 | 基数排序 | $O(d(n+r))$ |
| 数据链式存储 | 直接插入 / 归并 | 无需随机访问 |
